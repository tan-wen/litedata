# 指标管理

在侧栏“数据治理 → 指标管理”进入 `/metrics`。ADMIN / DEVELOPER 可维护指标，VIEWER 可查看定义、SQL 和历史。指标列表支持名称、编码、主题域、负责人搜索和类型筛选，使用数据库分页；新增、编辑、详情分别使用独立页面。

## 三类指标

| 类型 | 定义 | 例子 |
| --- | --- | --- |
| 原子指标 | 一个逻辑模型上的基础数值聚合，支持 SUM、COUNT、COUNT DISTINCT、AVG、MIN、MAX | 按 region 汇总订单 amount；COUNT(*) 统计订单行数 |
| 派生指标 | 一个原子指标 + 滚动时间窗口 + 可选业务筛选；继承其模型、度量和维度 | 最近 7 天、status = 'paid' 的订单金额 |
| 复合指标 | 引用已有指标，通过四则运算和括号计算；输入必须有相同维度 | `[paid_amount_7d] / [paid_orders_7d]` 得到最近 7 天客单价 |

每个指标都必须填写编码、名称、主题域、负责人和口径说明，单位可选。编码以小写英文字母或下划线开头，允许数字，最多 64 字符；编码、类型在首次保存后固定，编码在归档后仍占用。

## 配置顺序

1. 在“数据建模”登记来源表和字段。原子指标关联的是 Doris `warehouse` 库中的逻辑表。保存指标并不建表或写入数据；实际使用 SQL 前应完成建表、结构核对及数据接入。
2. 新建原子指标 `order_amount`：选择订单模型、SUM、度量字段 `amount`，维度填写 `region`，时间字段填写 `occurred_at`。COUNT 允许 `*`；COUNT DISTINCT 需要真实字段，其他聚合需要数值字段。时间字段必须是 DATE / DATETIME。
3. 新建 `order_count`：同一模型、COUNT、`*`，使用相同维度和时间字段。维度可留空，表示总体聚合；最多 10 个，按字段名规范化排序。`metric_value` 为输出保留字段名，不能用作维度。
4. 新建派生指标 `paid_amount_7d`：引用 `order_amount`，窗口为 7 天，筛选填写 `status = 'paid'`。再以相同窗口、筛选从 `order_count` 派生 `paid_orders_7d`。
5. 新建复合指标 `avg_paid_order_7d`，公式填写 `[paid_amount_7d] / [paid_orders_7d]`。保存后可查看 SQL、依赖版本及历史口径。

派生窗口是以数据库当前时间为终点的滚动区间 `[CURRENT_TIMESTAMP - N DAY, CURRENT_TIMESTAMP)`，不含未来时间。最多 3660 天；这不是自然日或业务日结算周期。时间字段应与仓库会话时区保持一致，当前界面不执行时区转换。原子指标不限制时间，时间字段仅供派生指标使用。筛选支持模型字段与字符串/数值常量的比较（`= != <> > >= < <=`）、`IN`、`IS NULL` / `IS NOT NULL`、AND / OR 和括号；字符串使用单引号，内部单引号写两次。不接受函数、子查询、脚本、字段间比较或任意 SQL。

复合公式支持数字、`[指标编码]`、`+ - * /`、一元正负号和括号，最多引用 10 个不同指标。每次除法都会使用 NULLIF 保护，除零结果为 NULL。无维度时合并各输入的单行聚合；有维度时取所有输入维度键的并集，使用 NULL 安全等值关联，缺失输入保留为 NULL，不自动补零。维度字段名称一致不代表业务口径兼容；配置人仍须核对时间范围、过滤条件、数据域、单位和去重方式。维度未包含某个时间字段时，该字段不会自动成为分组键。

## 版本与依赖

每次保存都会新增不可变版本，记录完整定义、生成的 SQL、上游指标版本、模型版本和操作人，并写入操作审计。SQL 预览展示保存时的快照；上游修改不会自动改变已保存的下游口径。要采用新的上游版本，需进入下游编辑页面核对后再次保存。来源模型变化后，应先重新保存原子指标，再更新派生指标。保存和归档使用版本校验，过期页面不能覆盖新的修改；依赖图修改串行化并检查自引用和循环。

当前详情 `/metrics/{id}` 展示最新活动定义；`/metrics/{id}/versions/{version}` 展示指定的只读快照。历史列表使用数据库分页，保存时间按北京时间展示。归档保留所有版本和 SQL；存在活动下游引用时不能归档，逻辑模型仍被活动指标引用时也不能归档。先调整或归档下游，再归档上游。归档后的历史仍可通过已有版本链接读取。

## 执行边界

本模块负责指标定义和 SQL 生成，不直接查询业务数据、不创建定时任务、不自动发布数据 API。需要落表时，将核对后的 SELECT 配合目标表的 INSERT INTO 放入“SQL 加工任务”；需要查询服务时，在“数据服务”配置和审核 SELECT，并沿用其授权、参数、限流及审计。指标修改不会同步修改已经复制到加工任务或数据服务中的 SQL。

SQL 输出列为配置的维度和 `metric_value`，最长 20000 字符。复合指标会展开保存的上游 SQL，过深或过大的嵌套会被拒绝。自动化测试使用真实 MySQL 验证迁移、CRUD、权限、页面和代表性 SQL 计算；Doris 的实际性能、容量和与现有引擎任务联动仍须在目标环境验证。
