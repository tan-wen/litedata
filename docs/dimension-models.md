# 公共维度建模（DIM）

DIM 保存跨业务复用的成员及描述属性，例如企业、产品、园区和日期。ODS 保存来源结构；DIM 在 ODS 之上统一编码和属性；事实加工可以关联 DIM，也可以把常用属性写入 DWD 宽表。DIM 是公共分支，不要求每个事实来源都经过 DIM。

## 建模与更新

1. 在“数据建模”点击“新增公共维度”，或在普通模型表单选择 DIM。
2. 定义业务键、展示名称字段（可选）和其他维度属性。业务键支持 1–10 个字段，按逗号分隔，必须与物理主键字段及顺序一致；主键连续位于字段前缀且不可空。
3. 更新策略为 SCD1：按业务键保留当前值。重复写入相同业务键会覆盖原属性；字段类型、主键及分桶沿用已有 Doris 建模约束。
4. 保存、预览并确认建表。模型详情展示业务键、展示字段、更新策略和字段的维度角色；模型修改后需重新核对物理结构。
5. 在“数据加工”为 DIM 配置一条 `INSERT INTO ... SELECT`，选择 ODS 同步为上游；为事实加工选择 DIM 加工为上游。只有上游成功后才运行下游，共享节点在同一依赖链中只执行一次。

示例结构：`dim_enterprise(enterprise_id BIGINT 主键, enterprise_name VARCHAR(128), product_code VARCHAR(32))`。业务键填写 `enterprise_id`，展示名称填写 `enterprise_name`。

```sql
INSERT INTO dim_enterprise (enterprise_id, enterprise_name, product_code)
SELECT enterprise_id, enterprise_name, product_code
FROM ods_enterprise;
```

下游事实可以关联 `dim_enterprise` 获得统一企业属性。维度加工和事实加工仍由配置人编写 SQL、声明依赖；业务键配置不自动生成 ETL、JOIN 或外键约束，也不自动绑定指标里的同名统计维度。

## 数据语义与质量

- SCD1 属性更新覆盖旧值，不增加成员版本；使用当前维度关联历史事实时，历史事实会按当前属性分类。已写入事实宽表的属性，需要重新加工相应事实后才会更新。
- 业务键应稳定。名称等易变属性不能代替成员身份；多系统相同编码存在冲突时，可以使用系统编码与源业务编码组成复合键，也可以在加工中显式统一映射。
- SQL 来源应对每个业务键输出一行；不要依赖同一批重复键的写入次序选择正确属性。可在源端或 ODS 配置业务键非空、唯一性检查，在 DIM 配置展示名称非空白和成员数检查。
- 事实表可通过数据质量的“引用完整性”规则检查成员是否存在。该规则当前为同库单字段引用检查，不代表数据库强制外键；复合业务键需要自定义异常 SQL。没有默认未知成员，配置人应明确迟到或缺失维度的隔离、默认成员及回补策略。
- `INSERT SELECT` 不会删除源端已消失的成员；可使用停用状态属性，或另行制定对账和成员清理流程。源端时间水位同步的硬删除及迟到边界仍适用。
- 当前不提供 SCD2 拉链、代理键生成、有效期 JOIN、层级编辑器、自动编码映射或自动历史回补。模型版本是结构配置版本，不是成员的历史版本。

## 升级与验证

Flyway `V11__dimension_models.sql` 仅为平台模型表新增业务键、展示字段、更新策略三列，既有模型默认为空，不改动已有 Doris 表。非 DIM 模型保存时清空维度配置；切换 DIM 需要显式定义合法业务键。

Maven 回归覆盖维度校验、保存/编辑、表单、DIM 分层分页筛选、元数据与血缘，以及 DIM → DWD 加工依赖。Doris 和 DS 在这些集成测试中为 mock；真实引擎验证使用独立的[化工园区 DIM 示例](../examples/chemical-park-dim/README.md)，包括属性更新后成员数保持不变、事实宽表重算及恢复数据后的 API 对账。[原版示例](../examples/chemical-park/README.md)保留直接关联 ODS 企业档案的流程。

历史实测覆盖独立 DIM 示例的多轮同步/加工、SCD1 更新与恢复、成员数不变、维度及事实引用质量、指标/API 对账和维度字段血缘；生成报告与看板保存在 Git 忽略的 `output/`。这些记录不包括 SCD2、生产容量、连续运行或自动定时触发的验收，每次发布仍需按示例重新验证。
