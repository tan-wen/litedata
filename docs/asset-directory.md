# 资产目录

打开“数据治理 → 资产目录”（`/assets`），统一检索物理表、逻辑模型、指标和数据服务。
目录从平台现有资源实时查询，无须重复登记，也不需要额外同步任务。

## 发现与理解资产

- 物理表来自已采集的 MySQL / Doris 元数据；尚未采集的表不会自动出现。进入“元数据与血缘”采集后即可在目录发现。
- 逻辑模型、指标和数据服务来自各自管理模块。物理表与逻辑模型是不同类型的资产，同名时也分别展示。
- 支持名称、编码、说明、标签、来源等关键词搜索，以及类型、主题域、负责人、标签和状态筛选。主题域、负责人和单个标签采用精确匹配。
- 列表使用数据库跨类型计数和分页，默认每页 20 条，翻页与调整每页条数保留筛选条件。顶部统计显示所有类型的全局数量，包括归档和未发现资产。
- 详情展示业务信息、原资源入口及可关联的字段结构、血缘、质量任务。模型的字段结构来自 `warehouse` 中同名 Doris 表的采集快照；尚未采集时为空。指标血缘跳转到现有指标血缘页面。
- 质量任务按来源与表名关联，避免不同来源的同名表混用；最多展示最近创建的 10 个活动任务及各自最近一次执行结果，可继续进入任务查看历史。没有质量任务不代表质量已通过。

## 维护业务描述

ADMIN / DEVELOPER 可以从资产详情进入独立的“编辑目录信息”页面，维护业务名称、主题域、负责人、业务说明、标签、更新频率和敏感级别。VIEWER 只能查看。

这些信息保存在独立的 `asset_profile` 表中，不修改模型、指标、元数据或服务定义。业务名称、主题域、负责人和说明留空时，实时继承原资源的对应字段；原资源没有定义时显示为空。填写后则使用目录描述覆盖展示。标签最多 10 个，每个最长 50 字符，使用逗号分隔，保存时去除重复项。

目录描述带版本检查，同时编辑时后保存的过期表单会被拒绝。保存行为记录操作人和审计事件。更新频率是人工声明，不等于实际数据更新时间；结构采集时间也不表示业务数据新鲜度。页面时间均为北京时间。

敏感级别为内部、公开、敏感，默认内部。它是描述标签，不改变系统的授权规则。目录与现有管理页面一样要求登录，不提供资产级权限申请或审批；数据服务继续要求有效的 API Key，目录不会展示或生成凭证。服务详情提供调用路径与现有调用记录入口。

## 状态与边界

- 活动：逻辑模型、指标尚未归档，或物理表在最近完整采集中存在；不代表已建表、数据就绪或质量通过。
- 已归档：模型或指标保留历史信息。归档指标的原资源与血缘入口指向其归档版本。
- 未发现：最近一次采集未发现物理表，或原数据源已移除。保留结构快照用于追溯，不保证物理表仍存在。
- 已发布 / 未发布：跟随数据服务当前发布状态。未发布的服务不能调用。

资源生命周期实时反映在目录中。原资源被物理删除后不再出现在目录，即使曾维护业务描述，也不能单独访问或编辑该描述。
目录不执行数据采集、数据查询、质量扫描、自动分类或数据权限审批，也不引入独立发布流程。

## 升级与验证

启动时由 Flyway 执行新增迁移 `V8__asset_directory.sql`，只创建目录描述表，不改写现有资源。

```powershell
.\mvnw.cmd verify
docker compose --env-file .env.example config --quiet
```

`AssetCatalogIntegrationTest` 使用真实 MySQL 验证迁移、跨类型分页、筛选、状态、详情跳转、描述继承、并发编辑、权限和 CSRF，以及不同来源的质量任务关联。自动化测试不代表 DataX / Doris / DolphinScheduler 完整链路验收。
