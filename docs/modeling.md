# 数据建模

本模块维护逻辑结构，并向当前单机 Doris 4.1.3 的 `warehouse` 建表。
新增 Flyway `V2__data_modeling.sql`，应用启动时自动升级平台元数据库，保留原有管道与服务数据。

## 使用流程

1. 第一步“模型信息”：填写物理表名、中文名称、主题域、数仓分层和说明。
2. 第二步“字段定义”：维护字段名、类型、键列、可空、注释和标准备注；键列须连续位于字段列表前面且不可空。
   数据类型使用下拉选择；CHAR / VARCHAR 单独设置长度，DECIMAL 设置总位数与小数位，DATETIME 设置 0–6 位时间精度。
   类型下拉和长度、精度控件在同一行；DATETIME(p) 的 p 表示秒后小数位数：0 为秒，3 为毫秒，6 为微秒，5 为 10 微秒精度。
   编辑已有模型时保留原字段的长度和精度；新增、移动或删除字段不会改变其他字段的类型参数。
   DIM 的业务键从本步骤的键列自动生成，避免重复录入不一致。
   可添加、移除和上下移动字段；最多 100 个。表名保存后固定，模型修改会增加版本。
3. 第三步“Doris 物理设置”：结合分层提示选择模型和副本，按需启用日期分区。
   分区字段只能从前一步的 DATE / DATETIME 非空键列中选择；无候选时不可启用日期自动分区。
   仅新增 DATETIME 字段还不够：若未勾选“键列”，第三步会指出具体字段并提供返回定位入口。
   确认该字段属于业务键后，需将它移到全部非键字段前面。不要仅为开启分区把会变化的更新时间加入 UNIQUE KEY；
   这会改变记录唯一性，应结合幂等更新需求选择稳定业务日期或不分区。
   AGGREGATE 的非键字段在本步骤选择聚合函数，SUM 只用于数值，REPLACE_IF_NOT_NULL 只用于可空字段。
   新增表默认自动分桶，无需填写桶数。前两步完成后显示摘要，第三步显示当前可用 BE 与总数，三个步骤卡片保持等高。
   点击可见步骤时保留当前浏览位置；从长表单底部切换时，仅在新步骤标题离开可视区域时定位内容。
   可返回修改；切换步骤只保留表单草稿，不写入数据库。
4. 保存并预览生成的 DDL，确认目标为 `warehouse` 后勾选确认、执行建表。
5. 检查执行结果，或对已有表执行“结构比对”。核对成功后状态为“已核对”，编辑后为“模型已变更”。
6. UNIQUE 模型可在“同步管道”或“数据加工”配置幂等写入；DUPLICATE / AGGREGATE 的写入与重算由独立作业管理。
   模型归档仅移除目录展示，保留物理表、模型字段与执行历史。
   已归档的表名仍占用，历史目前保留在元数据库中。

UNIQUE 模型的 ODS 数据来自业务库的 DataX 同步；其他分层通过 Doris `INSERT INTO ... SELECT` 写入。
现有管道保留同步后执行一条加工 SQL，例如 ODS → ADS；独立 数据加工与多层依赖编排已提供，
见 [数据加工](sql-transforms.md)。按日期重算与分区替换尚未提供。UNIQUE KEY 保证相同业务主键覆盖写入，但不会自动删除
因源数据删除或维度变化而失效的旧汇总行，后续加工任务需明确重跑和覆盖语义。

## 物理设置与选型

分层是业务组织方式，表模型取决于写入语义，平台不按 ODS/DWD/DWS/ADS 自动替用户切换模型。

| 表模型 | 键列含义 | 写入行为 | 常见用途 |
| --- | --- | --- | --- |
| DUPLICATE | 排序键 | 保留每次写入的明细，包括重复键 | 不需覆盖的原始事件、追加日志 |
| UNIQUE | 业务唯一键 | 同键覆盖，固定启用 merge-on-write | 增量同步、去重明细、可重复计算的汇总快照 |
| AGGREGATE | 分组键 | 同键的非键字段按指定函数合并 | 确定增量口径的汇总指标 |

AGGREGATE 支持 `SUM`、`MIN`、`MAX`、`REPLACE`、`REPLACE_IF_NOT_NULL`。`SUM` 仅用于数值类型；
`REPLACE_IF_NOT_NULL` 字段必须允许 NULL，输入 NULL 不会清空已有值。聚合模型不提供原始明细追溯；
重复导入一批 `SUM` 数据会再次累加。当前自动同步回放、任务重试与全量 `INSERT SELECT` 仍要求 UNIQUE 目标，
保存和执行时均检查登记模型类型。外部未登记的同步目标继续由管理员保证 UNIQUE 及业务键幂等性。

副本数可设为 1–10。新增、编辑及校验失败回显时，通过当前 Doris 建表连接执行 `SHOW BACKENDS`，显示可用 BE 数与总数，并动态限制输入上限。
可用数仅包含在线（Alive）、未退役（SystemDecommissioned=false）、支持存储（NodeRole=mix）且 location=default 的 BE，
与当前生成的 `replication_num` 默认标签分配一致；不包含宕机、退役、纯计算或其他标签节点。刷新页面会重新获取，保存和建表前也重新查询，
若副本数超过当前可用数（包括可用数为 0）则拒绝保存或建表。平台仍保留最多 10 副本的配置范围。
查询失败或建表账号未配置时，页面明确提示未获取到数量，不推测为单 BE；逻辑模型仍可保存，实际建表由 Doris 最终校验。
查询使用现有 writer 身份，不额外授予集群管理权限。当前 4.1.3 环境已实测原有 writer 可读取节点状态。
计数用于副本数量预检，磁盘容量及放置条件仍由 Doris 建表时检查。
副本负责冗余存储，桶负责数据分片；HASH 使用全部键列。

新版新增页默认生成 `BUCKETS AUTO`，隐藏手动桶数配置。Doris 在建表或创建新分区时推断桶数，
初始采用 Doris 的默认分区大小估算（10GB），后续新分区可参考历史分区数据。它不会自动重分桶已存在的数据，
也不意味着每个小表只占一个 Tablet，或保证比手工配置更快。当前 4.1.3 单 BE 实测初始日期分区为 10 桶。
自动分桶适合本平台减少初次配置的需求；大量小分区或明确的容量/并发要求仍须结合实际 Tablet 大小评估。

Flyway `V13__model_auto_buckets.sql` 为已有模型保留固定分桶标识和原桶数，不自动修改现有 Doris 表。
编辑旧模型时显示并保留原固定桶数；旧 API 客户端未提供 `autoBuckets` 时维持原固定分桶行为（1–32）。
结构核对比较 AUTO / 固定策略，只有固定策略才要求物理默认桶数等于逻辑桶数，不把 Doris 自动推断的数值误判为差异。

分区可选“不分区”或“日期自动范围分区”：选择 DATE / DATETIME 键列及日、月、年粒度，生成
`AUTO PARTITION BY RANGE(date_trunc(...)) ()`。Doris 在写入时按日期值创建相应分区，不预建空日期分区，
也不自动删除历史分区。当前配置面不包含手工 RANGE、LIST、动态分区过期策略或自由分区 SQL。
UNIQUE 的唯一性包含分区字段；应选择不可变业务日期，不能把可能变动的更新时间作为分区键后仍期待仅按订单 ID 覆盖。
DIM/SCD1 保持 UNIQUE 且不分区，以维护业务键的唯一当前值。

新增 Flyway `V12__model_physical_settings.sql`，已有模型升级后仍是 UNIQUE、单副本、不分区，原分桶数不变。
修改逻辑配置只生成新的 DDL 预览与核对项，不会更改已有 Doris 表。

## 当前边界

- 支持 ODS、DIM、DWD、DWS、ADS；DIM 提供业务键、展示名称字段、维度属性与 SCD1 当前值覆盖语义。操作、质量与历史处理边界见[公共维度建模](dimension-models.md)。

- 生成固定 `ENGINE=OLAP`，按上述结构化设置选择表模型、副本与日期分区；仅 UNIQUE 输出 merge-on-write 属性，新表默认 BUCKETS AUTO。
- 类型支持整数、BOOLEAN、DATE、DATETIME(0–6)、CHAR(1–255)、VARCHAR(1–65533)、STRING、
  DECIMAL(1–38, 0–精度)、FLOAT、DOUBLE。本期禁止 STRING 和浮点类型作为业务主键。
- 表中文名、业务说明和字段注释不接受反斜杠及控制字符：实测 Doris 4.1.3 的 COMMENT 会丢弃
  反斜杠。单引号采用 Doris 字面量转义，建表连接固定会话 sql_mode，保证解析一致。
- 只执行服务端生成的单条 CREATE TABLE，不接受用户提交任意 DDL。已有表创建会失败并留记录；
  核对已有表请用“结构比对”。没有自动 ALTER、DROP、结构回滚或 Doris 逆向导入。
- 比对信息来自 `information_schema.COLUMNS` 和 `SHOW CREATE TABLE`，覆盖字段名/类型/顺序/
  可空/注释、模型类型、键列、字段聚合函数、HASH 字段与分桶策略（固定时比较桶数）、默认副本数、日期自动分区规则及 UNIQUE merge-on-write。
  不比较表说明、业务分层/主题、标准备注、已创建分区列表及各分区单独覆盖的副本/桶属性或其他引擎属性。
- 标准备注当前为自由文本元数据，没有独立数据标准字典及强制映射。
- ADMIN / DEVELOPER 可修改、建表、比对及归档，VIEWER 可查看。页面写操作要求 CSRF。
  物理化前检查模型版本及预览摘要；保存、建表、比对和归档写审计，建表/比对保留版本、操作人、
  完整 DDL 快照与结果。详情展示最近 30 条执行记录，数据库保留全部记录。
- Doris DDL 与平台 MySQL 不能组成分布式事务。连接超时、进程中断或元数据库提交失败时，
  物理表可能已经创建，先比对结构确认结果。普通连接/执行异常返回脱敏信息并保留失败记录。

## 已有环境升级

新部署使用更新后的 bootstrap 自动授予 writer 在 `warehouse.*` 的 `CREATE_PRIV`。
已有环境可由 Doris 管理员执行以下最小授权（默认固定账号）：

```sql
GRANT CREATE_PRIV ON warehouse.* TO 'platform_writer';
```

随后从仓库根目录重建平台，让 Compose 新增的 writer 环境变量生效：

```sh
docker compose up -d --build --no-deps platform
```

只读查询账号保持 SELECT 权限。不要把 writer 密码填入模型或服务 SQL；凭据从本地环境注入。
独立部署应将建表权限限定在目标库，当前页面固定目标 `warehouse`。
