# 已确定的 v0.1 实现范围

依据本次确认更新 v4 的技术基线：Spring Boot 4.1.1、JDK 25、Thymeleaf、MyBatis Starter 4.1.0、
Bootstrap 5.3.8、MySQL 元数据库；DataX、Doris、DolphinScheduler 是固定依赖。部署按单机试点设计。

当前闭环：MySQL / PostgreSQL / SQL Server / Oracle 源表 → DataX 时间水位增量 → Doris UNIQUE KEY ODS → INSERT SELECT 加工 →
DolphinScheduler 按管道 Cron 调度/重试 → 只读 API、单服务凭证和调用审计。

## 分步验收
1. 基础平台：数据库迁移、登录和三种角色、页面服务端渲染、数据源加密与连通测试。
2. 同步和加工：先小样本对账，再验证新增/更新/失败重跑；DataX 成功写入 ODS 后推进水位，独立加工失败不回退水位。
3. 稳定调度：真实 DS 运行、定时执行、超时、重试、实例记录；中断后确认执行已停止再恢复。
4. 数据服务：发布/下线、参数绑定、固定 pageNum/pageSize 分页、凭证轮换、拒绝访问、限流和超时；调用明细及北京时间日调用量。
5. 容量与观察：同一环境记录百万行新增和更新批次、时间、CPU/内存/磁盘、源/ODS/加工结果对账；
   每批须在下一个小时窗口前完成，再执行连续七天观察。未取得实测结果前，不宣称性能或稳定性达标。

## 增量语义
水位字段为源表上的 DATETIME/TIMESTAMP，需索引，按源库时间获取上界。
读取区间为 [已成功水位 - 5分钟, 本次源库上界)，首批从 1970-01-01 开始。
DataX 失败不推进水位，重跑重复数据由 ODS UNIQUE 目标的业务主键覆盖；独立加工结果也须按其业务主键幂等写入，且失败不回退已成功同步的水位。

源端须在每次新增/更新时更新水位字段，且提交延迟在重放窗口以内。
任意晚提交、历史水位回写和硬删除无法由时间水位完整捕获；首版约定软删除字段随更新同步，
硬删除和超出窗口的迟到需业务对账与显式补数，不宣称 CDC 语义。
加工 SQL 是单条 INSERT INTO ... SELECT，仅允许 warehouse 库；首版加工整张 ODS，容量验收应包含此成本。
