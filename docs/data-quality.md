# 数据质量扫描

从“数据治理 → 数据质量”创建任务，选择 Doris 数仓或已登记的 MySQL 数据源，填写**连接所在库的单表名**、负责人，添加1至30条规则。保存后在详情点击“立即运行”，进入运行详情查看结果；刷新页面取得最新状态。任务列表和运行历史均使用数据库分页，列表支持按任务、表名、负责人搜索。

## 规则与参数

| 类型 | 检查方式 / 参数 |
|---|---|
| 非空、非空白 | 多列用逗号分隔，任意列异常即计一行；非空白同时检查 NULL、空串、仅空格 |
| 唯一性 | 支持联合键；重复组中所有行计为异常，NULL 也参与分组 |
| 数值范围、字符长度 | 参数1为最小值，参数2为最大值，包含边界 |
| 正则格式 | 参数1为数据库 REGEXP 表达式；MySQL 与 Doris 正则方言须按实际引擎验证 |
| 枚举 / 字典 | 参数1每行一个允许值，最多200项；匹配区分大小写与否遵循字段排序规则 |
| 非负、正数 | 分别检查 `<0`、`<=0` |
| 未来时间 | 时间字段晚于本次扫描开始时刻 |
| 新鲜度 | 参数1为最大延迟小时，检查 MAX(时间字段)；空值或未来时间不通过 |
| 数据量范围 | 参数1为最小行数，参数2为最大行数 |
| 合计范围、均值范围 | 单数值字段的 SUM / AVG，参数1下界、参数2上界；聚合为空不通过 |
| 字段比较 | 两列用逗号分隔，参数1为期望关系 `=`、`<>`、`>`、`>=`、`<`、`<=` |
| 引用完整性 | 单字段在同库引用表的引用字段中必须存在，NULL 不参与 |
| 数据量波动 | 参数1为最大变化百分比；相对上次**同任务版本、执行完成**的扫描，首批 WARNING 并建立基线；从0增至正数视为超限 |
| 自定义异常 SQL | 参数1填写返回异常行的受控 SELECT，仅支持 Doris warehouse 库；不支持注释、多语句、命名参数、锁及已禁止的副作用函数，沿用数据服务 QueryPolicy |

除非空、非空白、唯一性规则外，字段级规则中的 NULL 不计异常；如需约束 NULL，组合非空规则。空表的字段规则会通过，应按需加“数据量范围”。数值规则拒绝非数值字段，时间规则拒绝非日期时间字段，以避免数据库隐式转换产生错误结论。

每条规则均有异常条数、异常率两个容忍阈值，**两者都不超限**才通过，默认0表示不容忍。数据量、聚合、新鲜度和波动是一次指标判断，检测数为1，失败时异常数为1；其他规则按行计数。自定义 SQL 的分母为配置表行数和异常 SQL 返回行数的较大值；如 SQL 联表或聚合，该比例不等同于配置表的真实脏数据率。

## 执行与调度

- 留空 Cron 表示手动执行。设置六段 Spring Cron，例如 `0 0 2 * * *`（每日02:00），保存后在详情启用定时。时区为 `Asia/Shanghai`，15秒轮询到期任务，可能存在轮询和排队延迟。此调度由平台进程运行，适用于当前单机试点；平台离线期间不逐批补跑，恢复后对到期任务执行一批。
- 时间字段为空时全表扫描；否则常规内置规则只扫描 `[扫描开始时刻 - 窗口小时数, 扫描开始时刻)` 的行，避免未来时间污染聚合与数据量；“未来时间”规则保留窗口下界并去除上界，以便检测未来值。NULL 时间不在窗口内。SQL 规则的时间过滤需在 SQL 内自行配置，不能同时启用任务窗口。
- 时间参数和界面按北京时间解释；日期时间字段应使用相同业务时间口径。规则之间为独立只读查询，不提供跨规则、跨表的一致性快照；对账任务建议安排在写入结束后。
- 最多两个扫描并发，等待队列20批，同任务以数据库锁和运行标识互斥；运行时禁止修改配置、归档或变更调度。每条查询超时1到120秒，任务运行超过10分钟后不再启动后续规则查询。
- 修改配置会递增版本、暂停调度，重新确认后启用。执行记录保存当时配置快照、规则名称和统计，不回显 JDBC 原始错误或存储业务原始行。归档后保留历史记录。单机平台重启后，未完成批次标记 ERROR 并释放互斥，可手动重跑。

## 结果含义

- `PASSED`：所有规则在容忍范围内。
- `WARNING`：警告级规则超限，或波动规则尚未建立基线。
- `FAILED`：严重级规则检测到超限数据。
- `ERROR`：连接、字段、规则参数、查询执行或超时等原因导致扫描未完成；不能视为数据通过。
- `RUNNING`：后台执行中，刷新查看进度。连接失败时可能尚无逐条规则结果。

结果与操作写入现有审计表。查看需要登录；任务配置、运行、调度和归档仅限 ADMIN / DEVELOPER 并校验 CSRF。当前不发送外部告警，不自动修复数据，也不修改同步管道水位。

自动化测试使用真实 MySQL 执行查询并验证迁移、持久化、权限和页面。历史实测在 Doris 4.1.3 上以合成表和只读账号验证了全部18类规则的查询及预期异常数。这不代表其他 Doris 版本、复杂自定义 SQL、生产数据量或长周期调度的完整验收。
