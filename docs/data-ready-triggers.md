# 数据就绪事件与质量门禁

同步与加工独立调度。加工画布只编排 SQL → SQL，不接收同步节点，也不允许 SQL 任务直接依赖同步管道。

## 配置与执行

1. 同步管道可选关联一个质量任务。任务须检查该管道的 Doris ODS 目标表；规则可包含多个严重级（强）和警告级（弱）规则。时间字段留空时全表检查，填写时必须使用同步水位列，关联扫描使用本次同步固定的 `[lowerBound, upperBound)` 范围；独立质量扫描仍使用原时间窗口。
2. 在加工流程的新建或编辑信息页选择触发模式：`CRON` 或 `EVENT`。事件模式只选择一个同步管道作为来源，订阅其统一的数据就绪事件；配置来源后仍须在画布保存 SQL 并启用订阅。Cron 模式独立配置周期，不同时订阅事件。
3. 无质量任务时，同步成功即发布 `DATA_READY`。有关联质量任务时，同步成功后为本次同步创建独立质量运行；`PASSED` 或仅弱规则异常的 `WARNING` 才发布事件。强规则 `FAILED`、扫描未完成 `ERROR` 阻断加工并产生站内质量告警。严重级波动规则未建立基线时暂不放行，保存本次指标供后续检查建立基线。
4. 事件模式从来源同步管道运行，不能在加工流程手动运行以绕过门禁。独立手动或定时质量检查不发布同步批次的就绪事件。一个来源可供多个加工流程订阅，但每个加工流程只有一个来源，不提供多来源汇合或批次匹配。

DataX 成功即推进同步水位，质量或加工失败不回退水位。质量检查等待或运行期间禁止该管道再次领取同步、编辑或归档，以减少检查时的并发写入；这不是跨表快照或数据版本隔离，加工仍读取持续更新的 ODS。时间水位也不证明业务日期数据已完结。

## 记录与告警

- 同步运行详情分别显示同步状态、质量门禁状态及质量详情链接。质量运行保存同步批次编号与规则配置快照，不复用其他批次的扫描结果。
- “数据质量 → 质量告警”保存弱规则、强规则和扫描错误的站内告警，按数据库分页展示。当前不发送邮件、短信或外部消息。
- 加工流程的“事件记录”展示来源批次、质量运行、事件及投递状态。`SUBMITTED` 仅表示调度引擎接受请求，实际加工结果以运行记录为准。

## 持久化与暂停

运行终态、就绪事件和当时已启用的订阅投递记录在同一数据库事务中保存；事件以来源同步运行去重，每个事件和加工流程只创建一条投递。后台轮询会恢复未处理记录；加工任务互斥冲突时继续等待，已提交的相同定义由引擎串行排队。

启用订阅只接收随后发布的事件，不自动补历史事件。因加工配置校验失败而尚未提交的 `FAILED` 记录，在修复并启用原来源后可从事件页显式重试；已提交和结果未知记录不能重试。暂停订阅停止后续投递，尚未提交的记录取消；已进入提交或已提交的任务继续处理。重新启用产生新的订阅代次，旧代次待投递记录不再执行。修改来源、触发模式、SQL 或依赖前须暂停订阅。

平台先持久化 `SUBMITTING` 再请求引擎；响应丢失或提交中重启会保留 `UNKNOWN`，需核对引擎实例，禁止自动重发造成重复加工。引擎提交与平台数据库不是分布式事务，不承诺端到端恰好一次执行。

## 执行节点与验证

同步执行器在 DataX 成功回调后等待本批质量终态：通过和弱规则告警返回 0，强规则或扫描错误返回非 0。等待超过12分钟也返回非 0，此时扫描可能仍在排队，应查看平台最终门禁状态。绑定质量的同步节点不启用引擎自动重试，超时65分钟；未绑定质量的同步节点保留原重试与超时策略。平台与 worker 必须同时更新。

Flyway V25 只新增配置字段、关联与持久化事件/投递/告警表，不迁移旧混合同步加工图。开发测试使用新模式重建配置；已执行的旧迁移保持原样。

运行 `./mvnw verify`、`python -m unittest discover -s deploy/tests -v`。完整环境可运行 `python deploy/transform_smoke.py` 验证无质量事件触发、Cron 和 SQL 失败阻断；`python deploy/readiness_smoke.py` 验证强规则阻断、弱规则和通过规则放行，后者会向 demo-mysql 写入合成订单以产生新同步批次。两者保留独立测试资源作为证据。数据库和 mock 引擎测试不代表真实引擎或容量验收，合成数据冒烟也不代表生产容量验收。
